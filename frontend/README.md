# frontend/ — веб-интерфейс Kassa Sentinel (A15)

Веб-интерфейс проверяющего: загрузка .mov → прогресс анализа → отчёт с вердиктом, эпизодами, таймкодами,
кадрами-доказательствами и нормами РК. **Vite 6 + React 18 + TypeScript 5.9 + Tailwind 3.4**.
Язык — русский; светлая и тёмная темы; адаптивная вёрстка от 375 px; есть печатная версия отчёта.

Офлайн-контур банка: шрифты (Inter, Manrope — `@fontsource-variable`, OFL-1.1) и иконки (`lucide-react`, ISC)
собираются в бандл, **CDN не используются** (в `dist/` нет внешних URL, кроме ссылок на нормы adilet.zan.kz).
ML-моделей во фронтенде нет: `models.json` = `[]`.

## Запуск

```bash
cd frontend
npm ci                 # один раз, нужен интернет (потом офлайн); Node ≥ 18.18
npm run build          # tsc --noEmit + vite build → frontend/dist (A02 раздаёт его на "/")
npm test               # vitest: 53 теста, без браузера и без бэкенда
npm run dev            # :5173, прокси /api и /ui → VITE_PROXY_TARGET (по умолчанию http://127.0.0.1:8000)
npm run preview        # раздать собранный dist локально
```

Синтетическое демо без бэкенда: `/?demo=1` (`#/job/demo` — отчёт с нарушениями, `#/job/demo-clean` — без нарушений,
кнопка «Симуляция обработки» показывает степпер). В демо-режиме всегда видна лента **«СИНТЕТИЧЕСКОЕ ДЕМО»**,
реальные файлы не загружаются и не анализируются, нормы — явные заглушки `[ДЕМО]` (без выдуманных пунктов).

Необязательные скрипты (нужен Playwright: `npm i -D playwright` или `PLAYWRIGHT_MODULE=/path/to/playwright`;
Chromium — `CHROMIUM_PATH`):

| Скрипт | Что делает |
|---|---|
| `npm run screenshots` | Скриншоты **только синтетического демо** → `screenshots/*.png` (для питча) |
| `npm run e2e:mock` | e2e реального (не демо) HTTP-пути, бэкенд подменён синтетическими ответами в формате A02 — 15 проверок |
| `npm run e2e:real` | e2e против живого сервера: `E2E_BASE_URL=… E2E_KEY=… E2E_VIDEO=… node scripts/e2e-real.mjs`. Скриншоты — только при `E2E_SHOTS=<папка>`. **С реальными видео скриншоты не коммитить и никуда не отправлять** |

## Путь пользователя

1. **Вход.** `GET /ui/v1/session` → 401 → форма «Вход для проверяющего». Ключ доступа (или пароль UI) →
   `POST /ui/v1/session {api_key, password}` → сервер ставит HttpOnly cookie и возвращает `csrf_token`.
   Ключ не сохраняется: его нет ни в localStorage, ни в URL, ни в бандле. CSRF-токен хранится только в памяти вкладки.
2. **Загрузка.** Drag&drop или выбор файла; проверяются расширение `.mov`/`.mp4`, MIME-тип и размер
   (`VITE_MAX_UPLOAD_MB`, по умолчанию 1024; лимит сервера A02 — 300 МБ). Реальный прогресс XHR `upload.onprogress`,
   скорость загрузки, отмена. `POST /ui/v1/analyze` (multipart, поле `file`) с заголовком `X-CSRF-Token`.
3. **Обработка.** Опрос `GET /ui/v1/jobs/{id}` раз в 1,5 с. Степпер (6 шагов) строится по `stage`;
   процент выполнения и ETA показываются **только при наличии `progress` от сервера** (ETA — по скорости роста
   этого прогресса). Без него — неопределённый индикатор, без выдуманных чисел. Показываются `queue_position` и
   `elapsed_s` (A02). Сетевые сбои допускаются (до 10 подряд), а 401/403/404 сразу показывают понятную ошибку.
4. **Результат.**
   - баннер с формулировками ТЗ: «Обнаружены признаки возможных нарушений» / «Нарушение не обнаружено»;
   - плеер: только что загруженный файл играет локально (blob), повторно открытая задача — по
     `/ui/v1/jobs/{id}/video` (cookie + HTTP Range);
   - кастомная шкала: тепловая полоса индекса риска (`timeline`), интервалы эпизодов, пронумерованные маркеры
     (клик — перемотка), playhead, подсказка при наведении, перемотка с клавиатуры (←/→, Shift — шаг 5 с);
   - карточки эпизодов: тип и `type_id`, таймкод `mm:ss.s` (клик — перемотка и прокрутка к плееру), интервал,
     бейдж уверенности, описание, галерея кадров (лайтбокс: зум колесом, кнопками и двойным кликом, панорама,
     стрелки, Esc, кнопка «Перейти к моменту»), нормы (документ, пункт, раскрывающаяся цитата, ссылка на adilet,
     бейдж «цитата проверена» / «цитата не сверена» по `verified`), блок «Как система пришла к выводу»
     (facts и источники rules / temporal / vlm / fusion);
   - справа: навигация по эпизодам, Copilot (при 501 скрывается), «Что система не проверяет» (ТЗ §7),
     технические детали (`meta.timings`, `meta.models`, версия);
   - экспорт: **JSON по схеме ТЗ** (для жюри — только обязательные поля), **полный JSON** (нормы, timeline, meta),
     **печать / PDF** (отдельные print-стили: шапка отчёта, раскрытые цитаты, URL ссылок, без плеера и чата).
5. **История.** Список «Недавние проверки» объединяет локальную историю (localStorage, только job_id, имя файла
   и вердикт) и серверную (`GET /ui/v1/jobs`).
6. **«О системе».** Принципы работы, схема пайплайна, типы V01–V08/V99, модели и лицензии (из `meta.models`
   последнего анализа или список по архитектуре), бейдж «Работает полностью локально».

### Правила честности интерфейса
- **Failed или неполный анализ никогда не показывается зелёным.**
  - `status: failed` → жёлтый баннер «Анализ не завершён»; если A02 передал `partial`, показывается найденное до сбоя.
  - `done` + признаки неполноты (`meta.partial | incomplete | degraded | timed_out`, `complete: false`,
    непустые `skipped_stages | stages_skipped | failed_stages`, предупреждения с partial / timeout / skipped /
    неполн / таймаут / пропущ) → «Анализ неполный», нужен ручной просмотр.
  - Зелёный «Нарушение не обнаружено» — только для `done` + `no_violation` без признаков неполноты.
- «Уверенность» подписана как внутренняя оценка модели, а не вероятность и не точность. Кривая риска подписана
  как «индекс риска (не вероятность)».
- Тексты описывают только видимое; блок «Что система не проверяет» есть на каждом отчёте.

## Структура

```
src/
  api/types.ts        типы ответа: обязательные поля ТЗ + доп. поля контракта v1
  api/normalize.ts    защитный разбор ответа: normalizeJob, toJuryJson, isPartial, imageSrc, inferDuration,
                      violationFacts, violationSources
  api/client.ts       HttpBackend (cookie-сессия, CSRF, XHR-загрузка, запасной путь /api/v1), ENDPOINTS, история
  api/demo.ts         DemoBackend + генератор синтетических SVG-сцен (вид сверху, головы размыты) — только ?demo=1
  lib/                format (таймкод и т. п.), verdict, stages, catalog (подписи V01–V99), validate, router (hash), theme
  components/         UploadScreen, ProcessingView, ResultView, VideoPlayer, RiskTimeline, ViolationCard,
                      Lightbox, NormCard, CopilotPanel, AboutScreen, SettingsDialog, Header, ui
tests/                vitest: format, normalize (формы ответов из contracts/examples A01), verdict, demo, SSR-рендер экранов
scripts/              screenshots.mjs, e2e-mock.mjs, e2e-real.mjs, pw.mjs
screenshots/          снимки синтетического демо и мок-e2e (реальных кадров нет)
```

Роутинг через hash (`#/`, `#/job/<id>`, `#/about`), поэтому `dist` раздаётся с `/` одним `index.html`;
`base: "./"` позволяет раздавать и из подкаталога.

## Какие маршруты использует UI (сверено с веткой A02)

| Метод и путь | Авторизация | Назначение |
|---|---|---|
| `GET /ui/v1/session` | cookie | 200 `{authenticated, csrf_token}` или 401 `{authenticated:false, password_login}` |
| `POST /ui/v1/session` | тело `{api_key, password}` | вход → HttpOnly cookie (path `/ui/v1`) + `csrf_token` |
| `DELETE /ui/v1/session` | cookie | выход |
| `POST /ui/v1/analyze` | cookie + `X-CSRF-Token` | multipart `file` → `{job_id}` |
| `GET /ui/v1/jobs/{id}` | cookie | статус и результат (схема ТЗ + доп. поля; у failed — `partial`) |
| `GET /ui/v1/jobs?limit=20` | cookie | серверная история |
| `GET /ui/v1/jobs/{id}/video` | cookie | видео для `<video>` (Range) |
| `POST /ui/v1/jobs/{id}/ask` | cookie + `X-CSRF-Token` | Copilot `{question, history}` → `{answer, sources?}`; 501 → панель скрыта |
| `/api/v1/*` | `X-API-Key` | запасной путь, если `/ui/v1` выключен (404/405): ключ из «Настроек», только в памяти вкладки |

Все пути собраны в `src/api/client.ts` → `ENDPOINTS`. При 403 на POST (устарел CSRF после перезапуска сервера)
сессия перечитывается и запрос повторяется один раз. При 401 на `/ui/v1/*` и наличии ключа в памяти запрос
повторяется через `/api/v1/*`.

## Настройки и переменные

| Имя | Где | Назначение |
|---|---|---|
| `VITE_PROXY_TARGET` | dev | адрес бэкенда для прокси `npm run dev` |
| `VITE_API_BASE` | build | префикс API, если UI раздаётся не тем же сервером (по умолчанию — тот же origin) |

## Проверки, которые реально выполнены

- `npm run build` — без ошибок TS, бандл ≈ 280 КБ JS (86 КБ gzip) + 51 КБ CSS + локальные шрифты.
- `npm test` — 53 теста: форматтеры, нормализатор на формах ответов из `contracts/examples` (A01), вердикт
  (failed/partial не зелёные), стадии, валидация файла, роутинг, демо, SSR-рендер экранов.
- `npm run e2e:mock` — 15 проверок: вход (неверный и верный ключ), ключ не попадает в localStorage и URL,
  CSRF на всех POST, очередь и реальный прогресс, результат, перемотка по таймкоду, лайтбокс, норма,
  Copilot 501, серверная история, failed / failed+partial / partial / clean.
- `npm run e2e:real` против **ветки A02** (fake-пайплайн, синтетический ролик ffmpeg `testsrc2`): вход по cookie,
  загрузка с CSRF (200), результат за ≈ 5 с, перемотка, кадр, `/ui/v1/jobs/{id}/video` → **206** и воспроизведение,
  без ошибок JS.
- Вёрстка на 375 px без горизонтальной прокрутки (проверено скриптом: загрузка, отчёт с нарушениями, отчёт без нарушений, «О системе»).

GPU, реального пайплайна и реальных данных в этой среде нет — скорость анализа и качество детекции не измерялись.

## Ограничения

- Воспроизведение `.mov` (H.264) зависит от браузера: Chrome и Edge его играют, сборка Chromium из Playwright — нет
  (проверено на синтетическом ролике). Если A02 создаёт `preview.mp4`, плеер получает его автоматически. Без видео
  отчёт полностью работоспособен: кадры-доказательства и таймкоды остаются.
- `facts` и `sources` у нарушения — необязательные поля. Без них UI берёт факты из `meta.events[]` (по `type_id`
  и ±15 с), а если и их нет — из предложений `description`.
- История в localStorage — только на этом устройстве. Серверная история зависит от `GET /ui/v1/jobs`.
- Демо-нормы — заглушки; реальные ссылки приходят только из `norms/catalog.yaml` через сервер.

## Для интегратора

1. **Раздача.** A02 уже отдаёт `frontend/dist` на `/` (`frontend_dir: frontend/dist`). В Docker (A17) нужен
   этап `cd frontend && npm ci && npm run build` (Node ≥ 18.18); `node_modules` и `dist` в git не попадают (`.gitignore` A01).
2. **A02.** Маршруты из таблицы выше уже совпадают с веткой A02. При запуске ветки A02 в чистом venv загрузка падала
   с 500: `ModuleNotFoundError: python_multipart` (`uploads.py: _receive_multipart`). Нужно добавить
   `python-multipart` в зависимости A02/A17.
3. **A03 / A12 (fusion) / A01.** Пожалуйста, отдавайте:
   - `meta.duration_sec` — для шкалы, если видео не загрузилось;
   - флаги неполноты (`meta.partial` или `meta.skipped_stages`) — для честного вердикта;
   - по возможности `violations[].facts[]` и `violations[].sources[]` (или `meta.events[]` с `type_id`, `t_peak`,
     `source`, `facts`) — для блока «Как система пришла к выводу».

   Сам контракт не меняется: это доп. поля через `meta` / `extra`.
4. **A13 (нормы).** UI показывает `rules[]` (или `rule`) как есть: `document`, `clause`, `quote`, `url`, `verified`.
5. **A14 (Copilot).** `POST …/jobs/{id}/ask` с телом `{question, history:[{role, text}]}` → `{answer, sources?}`.
   Ответ 501 скрывает панель.
6. **A18 (питч).** Скриншоты синтетического демо лежат в `frontend/screenshots/`; живое демо открывается по `/?demo=1`.
