# A09 — `ml/rules/`: движок правил → события

Декларативные правила над рядами `SceneState` (сигналы A07/A08) + треки/зоны (A06) →
`list[Event]` (`source="rules"`). Без моделей и весов: numpy + PyYAML, работает одинаково
с `SENTINEL_MOCK=1` и без него. Обрабатывает 145-секундный ролик (≈725 кадров при 5 fps)
за миллисекунды, без GPU.

> Результат правил — **признаки возможного нарушения для проверяющего**, а не юридическое
> заключение. Правила не утверждают невидимое (допуск, умысел, сумму, подлинность).

## Принципы (после дополнения к задаче)

1. **V01–V08 — гипотезы, а не подтверждённая таксономия датасета.** ID сохранены для
   совместимости с `norms/catalog.yaml` (A13). Правило включается только при конкретном
   наблюдаемом условии, а не ради полноты списка (таблица ниже: 6 включено, 8 выключено).
2. **Юридический вывод только при проверенной норме.** У каждого события есть `extra["assessment"]`:
   - `candidate_violation` — правило вида `kind: violation`, видимые условия доказаны **и** у
     типа в каталоге A13 есть норма с `verified: true` и непустым URL;
   - `review_observation` — наблюдение для проверяющего без юридического утверждения: правило
     вида `kind: observation` (телефон, открытая дверь, еда, руки не видны, другой человек в кадре)
     **или** норма не проверена/отсутствует (в т.ч. встроенный fallback-каталог — в нём норм нет);
   - `insufficient_context` — условие могло выполняться, но этап не наблюдался полностью.

   Уверенность событий `review_observation` ограничена сверху 0.45, `insufficient_context` — 0.3,
   так что даже наивный порог 0.5 в fusion не превратит их в нарушение. `extra["legal_claim"]`
   всегда `False`.
3. **Отсутствие сигнала ≠ отрицание.** Неизвестное значение (сигнал не пришёл, окклюзия, пропуск
   дольше `ffill_max_s`) — это интервал `[lo, hi]`. Выражения считаются в интервальной
   (трёхзначной) логике: `lo` — доказано наблюдениями, `hi` — возможно. События строятся
   **только по `lo`**. Например, `min(safe_open, not cashier_present)` при неизвестном кассире
   даёт `lo=0`, «кассир ушёл» не выводится.
4. **Нарушение «по бездействию» требует наблюдаемого полного этапа** (`inaction:` в YAML):
   предшествующее состояние доказано за `before_window_s` до начала (например, кассир у открытого
   сейфа); начало не обрезано (не в первые `edge_s` ролика); покрытие наблюдениями ≥ `min_coverage`.
   Если ролик заканчивается раньше `min_duration_s` — `insufficient_context`. Если якорь доказан
   (`anchor:`, например «сейф открыт»), а остальное неизвестно — тоже `insufficient_context`.
5. **`t_peak` — фактический момент доказательства, а не «onset + 0.5 с».** Политика по умолчанию
   `evidence`: самый ранний кадр сегмента, где доказанная сила близка к максимальной
   (`evidence_tol`). Это реальный кадр ряда. Есть и `onset | max | center | onset_plus`, но сдвиги
   и пороги калибруются **только на train/calibration** через `replay`, не на тесте.
   `extra["evidence_t"]` — до 3 фактических моментов (начало, `t_peak`, максимум) для кадров-доказательств.
6. **Факты — только наблюдаемое.** Если значение для плейсхолдера неизвестно, факт не печатается.
   Факты о полном этапе (`facts_stage`, «До этого кассир наблюдался…») печатаются только после
   пройденной проверки этапа. В fallback-каталоге нет норм, и их там быть не должно (правило 5).

## Публичные функции

```python
from ml.rules import run_rules                      # контракт v1
events = run_rules(states, tracks, zones, catalog)  # + необязательный config=RulesConfig

from ml.rules import evaluate, split_by_assessment, assessment_of, load_rules_config
report = evaluate(states, tracks, zones, catalog)   # RulesReport: events, series, strengths,
                                                    # possible, candidates, warnings, risk_curve(), summary()
groups = split_by_assessment(report.events)         # {"candidate_violation": [...], "review_observation": [...],
                                                    #  "insufficient_context": [...]}
cfg = load_rules_config()                           # rules.yaml (env SENTINEL_RULES_YAML переопределяет путь)
cfg.rules_table()                                   # таблица enabled/disabled с причинами

from ml.rules.cache_io import save_cache            # A03: сохранить states/tracks/zones для replay
save_cache("cache/", video_id, states, tracks, zones)
```

`catalog`: dict формы `norms/catalog.yaml`. Если он пустой или `None`, лениво пробуем
`norms.load_catalog()`, иначе берём `FALLBACK_CATALOG` (только имена типов, ничего не верифицировано →
кандидатов в нарушения не будет).

### Что лежит в `Event`

| Поле | Значение |
|---|---|
| `type_id` | `V01..V08` из каталога (гипотезы) |
| `t_start`, `t_end` | фактические кадры начала/конца доказанного сегмента, с |
| `t_peak` | фактический кадр-доказательство (политика `evidence`) |
| `confidence` | от силы и длительности, неубывающая по длительности; потолки для review/insufficient |
| `facts` | наблюдаемые факты по-русски по шаблонам `rules.yaml` |
| `bboxes` | боксы участников на `t_peak` из треков (`visitor#7`, `safe_open#3`, `zone:safe`) |
| `track_ids` | id треков из `bboxes` |
| `extra.assessment` | `candidate_violation` / `review_observation` / `insufficient_context` |
| `extra.assessment_reasons` | почему не кандидат (нет проверенной нормы, правило-наблюдение, причина неполного контекста) |
| `extra.norm_status` | `verified` / `unverified` / `absent` |
| `extra.evidence_t` | ≤ 3 фактических момента для кадров-доказательств |
| `extra.rule_ids`, `extra.merged` | какие правила одного типа слились в событие |
| `extra.trace` | «почему»: выражения, пороги, условия (`signal op threshold`, значение, ok/неизвестно), статистика сигналов по сегменту, слагаемые уверенности, отсутствующие и производные сигналы |
| `extra.suppressed`, `extra.yielded_to` | что подавил NMS, кому уступил тип |

## `rules.yaml`

Все пороги вынесены в YAML и пока стартовые: на реальных данных не замерялись.

- `global`: `ffill_max_s`, `merge_policy`, `derive_from_tracks`, `nms_window_s` (5 с),
  `same_type_merge_gap_s`, `max_events`, `min_confidence`, `require_verified_norm`,
  `emit_review_observations`, `emit_insufficient_context`, `observation_conf_cap`, `insufficient_conf_cap`,
  `derived_conf_factor` (×0.85, если правило опиралось на производные сигналы из треков).
- `signal_ranges` — диапазон неизвестного значения (по умолчанию `[0, 1]`, `n_persons: [0, 10]`).
- `signal_defaults` — явные исключения «нет ключа = значение»; по умолчанию пусто.
- Правило: `id`, `type_id`, `kind` (`violation`/`observation`), `enabled`, `status_reason` (обязательно),
  `comment` (какую норму/признак проверяет), `strength` (нечёткое выражение 0..1), `gate`
  + `gate_mode` (`strict`: gate должен быть доказан; `lenient`: блокирует, только если доказанно ложен —
  используется только для исключений, например инкассатора), `anchor`, `inaction`, `on`/`off`
  (гистерезис), `smooth` (медиана 0.6 с против одиночных вспышек), `min_duration_s`, `merge_gap_s`
  (дебаунс), `t_peak`, `confidence` (`base + w_strength·сила + w_duration·(1−e^(−d/τ))`, или `expr`),
  `facts`, `facts_stage`, `highlight` (`role:visitor`, `label:safe_open`, `zone:safe`), `yield_to`, `max_events`.

**Язык выражений** — собственный безопасный парсер на `ast` с белым списком (никакого `eval`,
`simpleeval` не нужен): `and`=min, `or`=max, `not`=1−x, сравнения, `+ - * /`, `min max abs clip
ramp step`, временные `was(x,w) held(x,w) avg(x,w) ahead(x,w) ever(x)`. Атрибуты, индексы, строки,
лямбды и вызовы вне белого списка отвергаются при загрузке.

**Антифлик**: медианное сглаживание → гистерезис `on/off` → склейка разрывов ≤ `merge_gap_s` →
отбрасывание короче `min_duration_s` → слияние перекрывающихся событий одного типа от разных правил
(бонус за подтверждение) → `yield_to` → NMS одного типа в окне 5 с → `min_confidence` → лимиты
`max_events` (на правило и всего).

## Replay: тюнинг по кэшу без CV

```bash
python -m ml.rules.replay --cache cache/ --labels data/labels.csv                 # прод-режим норм
python -m ml.rules.replay --cache cache/ --labels data/labels.csv --assume-verified \
    --set rules.V01_outsider_in_cashier_area.min_duration_s=3 \
    --sweep global.ffill_max_s=0.5,1,2 --sweep rules.V03_safe_left_open.min_duration_s=3,5,8
python -m ml.rules.replay --cache cache/ --labels data/labels.csv --json out.json --csv out.csv --events
python -m ml.rules.replay --rules-table
```

- Кэш (JSON, без pickle): `<cache>/<video>/states.json` (+ `tracks.json`, `zones.json`), или
  `<cache>/<video>.states.json[l]`, или `<video>.json` с ключами `states/tracks/zones`; `.gz` тоже.
  Состояние — `{"t", "signals": {...}}` или плоский словарь. Это `dataclasses.asdict` контракта v1.
- Разметка CSV: столбцы ищутся по заголовку (`file/видео`, `label/нарушение`, `second/секунда`),
  разделитель `, ; \t`, кодировка UTF-8 или cp1251. Значения — «нарушение / без нарушения», «22 секунда»,
  «0:22». Имена нормализуются: кириллическая `Х` ≡ латинская `X`, регистр, расширение и дефисы не важны.
- Вывод: таблица по видео (GT, вердикт, cand/review/insuff, тип, `t_peak`, Δt, попадание в `--tol`),
  TP/FP/FN/TN, precision/recall/F1, доля попаданий таймкода ≤ 1/2/3/5 с, медиана (GT − t_peak) —
  справочно; срабатывания каждого правила на чистых и нарушающих видео (источники FP).
- Вердикт — наличие `candidate_violation`. `--assume-verified` (только для калибровки) считает нормы
  всех типов проверенными, чтобы мерить детекцию отдельно от статуса норм. `--count-review` —
  диагностика: считать нарушением и `review_observation`.
- Дубликаты по md5 (Х-4≡Х-47 с разными секундами, Х-5≡Х-48) replay не склеивает: это разные строки
  разметки. При калибровке их стоит учитывать как один ролик.

## Ограничения

- Пороги, длительности и веса уверенности — стартовые, без замеров. Калибровать через `replay`
  на train/calibration (и проверять отдельно на отложенных роликах, включая другой ракурс).
- Правила знают только то, что дают сигналы A06–A08. Качество V01/V03 упирается в роли людей и
  авто-зону `cashier_area`, V02/V03/V07 — в `cashier_present`, V07 — в `cash_bag_visible` и
  `collector_present`.
- Новые типы нарушений из финального теста правила не найдут: это задача A10 (temporal) и A11 (VLM discover).
- Если в среде нет проверенных норм, вердикт по правилам всегда `no_violation`: все события станут
  `review_observation`. Это следствие требования «юридический вывод только при проверенной норме».

## Для интегратора

1. **A12 / fusion**: к вердикту `violation` допускать только события с
   `extra["assessment"] == "candidate_violation"` (`ml.rules.split_by_assessment`). `review_observation`
   показывать проверяющему как наблюдение без ссылки на норму как на основание. `insufficient_context`
   показывать как «недостаточно контекста». Кадры-доказательства брать по `extra["evidence_t"]`, боксы — из
   `bboxes`. Кривая риска правил — `evaluate(...).risk_curve()`.
2. **A03 / pipeline**: вызывать `run_rules(states, tracks, zones, catalog)`. `states` можно передать одним
   списком от `pose_signals` и `scene_states`: состояния с одинаковым `t` сливаются (`merge_policy: max`),
   разные частоты выравниваются. Для replay сохранять кэш через `ml.rules.cache_io.save_cache(...)`.
   Для UI полезен `evaluate(...).summary()` в `meta`: отсутствующие и производные сигналы, предупреждения.
3. **A07 / A08 (сигналы)**: если сигнал наблюдаем, слать его **явно, в том числе 0.0**. Отсутствие ключа
   означает «неизвестно», а не 0. Предполагается, что `outsider_in_cashier_area` исключает кассира и
   инкассатора (правила дополнительно гасят V01/V03, только если инкассатор доказан и людей ≤ 2).
4. **A06 (треки/зоны)**: имена зон из контракта (`cashier_area`, `desk`, `safe`, `door`) используются для
   производных сигналов (только когда сигнала нет в `states`) и для подсветки. Координаты не
   захардкожены. Роли `cashier`/`visitor`/`collector` — по зоне и поведению, не по лицу.
5. **A13 (нормы)**: статус берётся из `types.<V..>.rules[].verified` (bool `true` + непустой `url`).
   Без этого кандидатов в нарушения не будет.
