# ml/fusion — слияние, вердикт, кадры-доказательства, описания (A12)

Собирает события `rules` / `temporal` / `vlm` в итоговый `AnalysisResult`: группирует и сливает
события, выносит вердикт по порогам типов, подбирает 1–3 кадра-доказательства с реальным PTS,
пишет описание из наблюдаемых фактов и подставляет нормы из `norms/catalog.yaml`.
Моделей и весов нет (`models.json` = `[]`), GPU не нужен.

## Публичные функции

| Функция | Что делает |
|---|---|
| `ml.fusion.fuse(clip, events, risk, catalog, job_id) -> AnalysisResult` | сигнатура заморожена контрактом v1; `status="done"` |
| `ml.fusion.apply_completeness(result, stages) -> AnalysisResult` | неполный анализ: технический `failed` вместо «скрытого чистого» вердикта |
| `ml.fusion.result_to_jury(result) -> dict` | строгий ответ жюри: `contracts.serialize.result_to_api` (A01), если он есть; иначе fallback ровно по схеме ТЗ |
| `ml.fusion.result_to_ui_report(result) -> dict` | полный отчёт для UI: нормы со статусом сверки, подсказки, оверлеи, полнота |
| `ml.fusion.fuse_scores(...)` | чистое слияние без кадров (для тюнера и eval A16) |
| `python -m ml.fusion.tune --preds preds_raw/ --labels data/labels.csv` | подбор порогов (см. ниже) |

## Как работает

1. **Нормализация.** Времена приводятся к границам видео, `confidence` — к 0..1, источник — к `rules|temporal|vlm|fusion|other`.
   Неизвестный `type_id` превращается в `V99`, исходный тип сохраняется в `extra.orig_type_ids`.
   Битые события пропускаются, в `meta.warnings` пишется предупреждение. Принимаются `Event` и `dict`.
2. **Группировка.** События одного типа, между которыми не больше `grouping.merge_gap_s` (3 с), объединяются в одного кандидата.
3. **Скор.** Скоры rules, temporal и VLM **коррелированы**: все три источника смотрят на одни и те же кадры
   и используют общие детекции. Поэтому их комбинация — эвристический скор 0..1, а **не вероятность**.
   По умолчанию берётся `combine: max` от взвешенных скоров (`sources.*` в `config.yaml`) и добавляется
   небольшой ограниченный бонус за согласие источников (`agreement`, не больше 0.10).
   `noisy_or` оставлен только как опция: он предполагает независимость источников.
   Если ни одного temporal-события нет, поддержкой с весом `risk.support_weight` служит риск-кривая.
4. **VLM-понижение.** Если VLM уверенно отклонил событие, скор умножается на `vlm.reject_factor`.
   Поддерживаемые формы ответа VLM: `extra.vlm = {"verdict": "confirm|reject|unsure", "score": ..}`,
   `extra.vlm_verdict`, `extra.vlm_score`, `extra.vlm_confirmed`, `extra.verified: bool`.
   Событие `source="vlm"` с отказом засчитывается только как мнение VLM и само кандидата не поддерживает.
5. **Гейт «нарушение».** Кандидат попадает в `violations` только при одновременном выполнении условий (`report_gate`):
   - есть ≥ 1 конкретный наблюдаемый факт от `rules` или `vlm`, без слов-домыслов;
   - у типа есть норма в каталоге (если каталог недоступен целиком, нарушение выдаётся с предупреждением);
   - сигнал идёт не только от temporal;
   - скор ≥ τ[type] из `thresholds.yaml`;
   - кандидат не подавлен более сильным нарушением другого типа в тот же момент.

   Всё остальное уходит в `meta.ui.review_hints` с причинами (`reasons` / `reasons_ru`).
   **Высокая риск-кривая без фактов никогда не превращается в нарушение `V99`**: такие участки
   становятся подсказками `risk_only` «посмотреть человеку».
6. **Вердикт.** `violation`, если прошло хотя бы одно нарушение. В ответе не больше 10 нарушений:
   отбираются самые сильные, затем сортируются по времени.
7. **Таймкод.** Берётся `t_peak` самого весомого события (при равенстве приоритет у rules > vlm > temporal),
   привязывается к PTS реального кадра (сетка `clip.times`, иначе сетка `fps`) и округляется до 0.1 с
   в границах видео. Первый кадр-доказательство показывает именно этот момент.
8. **Кадры-доказательства** (`evidence.py`):
   - выбор моментов: `t_peak`, самый резкий кадр в окне `t_peak ± 1 с` (дисперсия лапласиана) и,
     для длинного события, кадр начала или конца. Кадры из разных моментов (≥ 0.4 с), визуальные дубли отбрасываются;
   - **в ответ жюри идёт чистый исходный кадр** без рамок и подписей. `timestamp_sec` = действительный PTS кадра:
     PTS сэмпла из `clip.times`, или `clip.frame_at_pts(t) -> (img, pts)`, если ingest его предоставляет;
   - **оверлеи для UI — отдельно**, в `meta.ui.evidence_overlays[i]`: JPEG с боксами и русскими подписями
     (роль/объект), штампом времени, подписью типа и тонкой рамкой по серьёзности, плюс векторные `shapes`
     (боксы и области размытия в нормированных координатах). Поля под текст добавляются сверху и снизу,
     так что содержимое кадра не перекрывается;
   - приватность: головы размываются **только по надёжной локализации** — по точкам головы COCO 0..4
     (`extra.keypoints` / `extra.poses`) или по явным `extra.head_boxes`. Эвристика «верхние 18% bbox»
     (`head_fallback: top_frac`) выключена: на потолочной камере верх бокса — не обязательно голова,
     и эвристика может закрыть руки и полезные действия;
   - JPEG ≤ 200 КБ: качество понижается ступенями, кадры больше 1280 px уменьшаются. Отдаётся base64 без префикса `data:`.
     Бюджет — `evidence.budget_s`; при его превышении остаётся 1 кадр на нарушение.
9. **Описание** (`describe.py`) — 1–3 предложения: что видно (факты) → почему это может быть нарушением
   («признак возможного нарушения») → «Требуется проверка человеком.». Если в каталоге есть
   `description_template` (`{t}`, `{facts}`, `{name}`, `{type_id}`, `{conf}`), используется он.
   Факты и предложения со словами-домыслами (`description.forbidden`: «украл», «мошенничество», «умышленно»…)
   вычищаются. В текст попадает **только сверенная норма** (`verified: true`).
10. **Нормы.** Берутся только из каталога (`norms.load_catalog()` или аргумент `catalog`).
    `verified` разбирается строго: строка `"false"` или мусор дают `False`, поэтому неподтверждённая норма
    никогда не выдаётся за сверенную. В UI-отчёте статус сверки виден явно.
    Встроенный fallback-каталог содержит только названия, шаблоны и серьёзность, **без ссылок на нормы**.
11. **Timeline** — шаг 0.5 с, значение = max(риск-кривая temporal, скор кандидатов на интервале).
    `meta.scores_raw` хранит входы (события и риск) и всех кандидатов: тюнер пересчитывает по ним слияние без повторного inference.

## Полнота анализа (согласовать с A03)

`fuse()` не видит, какие стадии упали, поэтому оркестратор после `fuse()` вызывает:

```python
from ml.fusion import fuse, apply_completeness
result = fuse(clip, events, risk, catalog, job_id)
result = apply_completeness(result, {"ingest": "ok", "detect": "ok", "rules": "ok",
                                     "temporal": "timeout", "vlm": "skipped"})
```

- Обязательная стадия (`completeness.required`: ingest, detect, rules) упала или не запускалась, нарушений нет
  → `status="failed"`, `verdict=None`, `meta.failure` с причиной. Пустой список после падения inference **не** превращается в `done/no_violation`.
- Обязательная стадия упала, но нарушения найдены → `verdict="violation"` сохраняется, `meta.analysis_complete=False`, `meta.ui.incomplete`.
- Упали только необязательные стадии (temporal, vlm, pose…) → вердикт остаётся, стадии перечислены в `meta.degraded`.
- Если внутри `fuse` случилась авария, работает аварийный режим. Событие с фактом ≥ τ даёт `violation` (без кадров), иначе `failed`.

Статус стадии можно передать как `"ok"`, `"failed: CUDA OOM"`, `True/False` или `{"status": ..., "error": ...}`.
Синонимы имён стадий (`detection`, `rule_engine`…) нормализуются.

## Подбор порогов

```bash
python -m ml.fusion.tune --preds preds_raw/ --labels data/labels.csv --holdout 0.3 --cv 5 \
    --out ml/fusion/thresholds.yaml --report tune_report.json
```

- Пороги подбираются **только на train-части**. Метрики (полнота, ложные, доля попаданий таймкода ±3 с) считаются
  на отложенной калибровочной части. Дубликаты с одинаковыми входами (Х-4≡Х-47, Х-5≡Х-48) всегда попадают в одну часть.
  `--cv K` оценивает саму процедуру через grouped K-fold. Подбор на всей выборке — только флагом `--fit-all` (с пометкой в YAML).
- Цель: полнота ≥ `--target-recall` на train, затем минимум ложных. Внутри плато равных решений выбирается точка
  ближе к нижней границе (`--bias 0.35`): это запас полноты для новых видео и другого ракурса.
- `preds_raw/<id ролика>.json` — ответ API, UI-отчёт, `AnalysisResult.meta` или голый `scores_raw`.
  Имена нормализуются: кириллическая `Х` → латинская `X`, расширение отбрасывается.
- CSV разметки распознаётся гибко: разделитель `,` / `;` / таб, кодировка UTF-8 или cp1251, колонки вида
  `video|file|видео`, `label|нарушение|разметка`, `second|секунда|таймкод`, значения «нарушение» / «без нарушения» / 1 / 0, «22 секунда», «0:22».

## Запуск и проверки

```bash
pip install -r ml/fusion/requirements.txt
python -m pytest ml/fusion/tests -q        # без GPU, видео и весов: синтетические клипы
```

Тесты (58) покрывают:
- слияние и дедуп событий;
- max-комбинацию с ограниченным бонусом и VLM-понижение;
- риск-кривую → только подсказка, temporal-only / без факта / без нормы → подсказка;
- неизвестный тип → V99, пороги по типам;
- таймкод в границах видео и на сетке PTS, лимит 10 нарушений, NMS между типами, timeline, битые входы;
- evidence: соответствие JPEG действительному PTS (номер кадра зашит в пиксели), base64 → валидный JPEG ≤ 200 КБ (включая 4K-шум),
  отсутствие дублей, выбор самого резкого кадра, fallback при сбое `frame_at`, размытие только головы по ключевым точкам,
  отсутствие эвристического размытия по умолчанию, чистый кадр жюри отдельно от оверлея UI, русские подписи, бюджет;
- описания без домыслов, 1–3 предложения, шаблоны каталога, цитирование только сверенных норм, строгий разбор `verified`;
- строгий сериализатор жюри, UI-отчёт;
- error vs clean (`failed` против `done/no_violation`), частичная деградация, аварийный режим;
- тюнер: парсеры, сплит с дублями, подбор, CLI end-to-end.

Без GPU и реальных данных измерений качества нет: все пороги и веса — стартовые эвристики,
их нужно перенастроить на данных команды через `tune` и eval A16.

## Конфиги и env

- `config.yaml` — все веса, пороги гейта, параметры evidence, описаний и полноты; отсутствующие ключи берутся из `config.py`.
- `thresholds.yaml` — τ по типам; при `tuned: false` это стартовые эвристики.
- Env: `SENTINEL_FUSION_CONFIG`, `SENTINEL_FUSION_THRESHOLDS` — пути к YAML;
  `SENTINEL_FUSION_NO_FRAMES=1` — без кадров (быстрый eval/тюнинг); `SENTINEL_FONT` — TTF с кириллицей для оверлеев.

## Зависимости и лицензии

numpy (BSD-3), opencv-python-headless (Apache-2.0), PyYAML (MIT), Pillow (MIT-CMU/HPND). Моделей нет.
Для кириллицы на оверлеях нужен TTF-шрифт: DejaVu/Liberation/Noto на Linux, Arial/Segoe/Tahoma на Windows.
Без шрифта текст транслитерируется и рисуется через `cv2.putText`.

## Ограничения

- `confidence` — эвристический скор, не откалиброванная вероятность.
- Если `frame_at(t)` у ingest ищет не ближайший кадр, а «первый кадр ≥ t», PTS по fps-сетке может отличаться на 1 кадр.
  Поэтому время берётся из `clip.times` или из `frame_at_pts`.
- Боксы `Event.bboxes` относятся к `t_peak`. На кадрах дальше `box_max_dt_s` от него боксы в UI-оверлее не рисуются.
- Без ключевых точек головы на кадрах не размываются (в `meta.warnings` об этом пишется предупреждение).

## Для интегратора

1. **A03 (pipeline):** после `fuse()` вызывать `apply_completeness(result, stages)` со статусами стадий.
   Для тюнинга сохранять `meta.scores_raw` в `preds_raw/<id>.json`, или просто весь ответ / UI-отчёт.
2. **A02 (API):** ответ жюри — `result_to_jury(result)`, то есть `contracts.serialize.result_to_api` от A01.
   UI-эндпоинт — `result_to_ui_report(result)`: оверлеи, подсказки, нормы со статусом сверки, полнота.
   `meta.ui.evidence_overlays` весит до ~200 КБ на нарушение, поэтому в строгий ответ жюри его не включать.
3. **A04 (ingest), предложение:** добавить `clip.frame_at_pts(t) -> (np.ndarray, pts_sec)`, чтобы получать точный PTS
   любого кадра. Сейчас используется сетка `clip.times`, а это и есть PTS сэмплов.
4. **A09 (rules) / A11 (VLM):** в `Event.facts` писать только наблюдаемые факты по-русски, без них событие станет подсказкой.
   Для размытия голов класть в `Event.extra` поля `keypoints` (`{name: COCO-17}`), `poses` или `head_boxes`.
   Ключи `Event.bboxes` — роль или метка с номером (`visitor:2`, `cashier`, `cash_bag`), чтобы получить русские подписи.
   Мнение VLM — `extra.vlm = {"verdict": "confirm|reject|unsure", "score": float}`.
   Для «лучшего типа» в подсказках по риск-кривой temporal может отдавать `extra.type_probs = {V01: p, …}`.
5. **A13 (norms):** fusion читает `types.<id>.{name, description_template, severity, rules[]}`. `verified` — YAML bool.
   Тип без норм (`rules: []`) по умолчанию даёт подсказку, а не нарушение (`report_gate.require_norm`).
6. **A15 (frontend):** `meta.ui.review_hints` — «спорные места» с `reasons_ru`; `meta.ui.incomplete` / `meta.failure` —
   баннер неполного анализа; `meta.ui.evidence_overlays[i].frames|shapes|norms`.
7. **A17 (deploy):** в Docker-образ поставить `fonts-dejavu-core`, иначе подписи будут транслитом.
8. Fallback-копия контракта `_contract_fallback.py` и импорт через `_types.py` нужны, пока ветка A01 не в main.
   Удалять fallback только после того, как в ветке появятся canonical `contracts`.
   **Предложение A01:** добавить в контракт v2 параметр `fuse(..., stages=None)` или поле полноты в `AnalysisResult`
   вместо отдельного вызова `apply_completeness`.
9. Ветка начинается от коммита A01 с контрактом, а `main` — от отдельного пустого корня: истории разные, их объединяет интегратор.
