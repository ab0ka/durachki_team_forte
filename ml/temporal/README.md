# ml/temporal — временная модель и генератор кандидатов (A10)

Признаки SigLIP2 замораживаются. На них работают **генератор кандидатов** `propose(clip)` (3–8 моментов
для VLM и правил) и обучаемая риск-кривая. `score(clip)` оставлен для совместимости с контрактом.
Результат — подсказка для проверяющего, а не юридическое заключение.

> **Чего здесь нет.** У A10 нет ни видео, ни GPU. Весь код проверен только на синтетике и mock-признаках.
> Реальные цифры даёт только замер L2 (команда ниже). Все 42 строки разметки уже использовались
> в разведочной оценке, поэтому любые метрики на них — **разведочные**, не независимый тест.
> В прод режим попадает только после измеренной пользы.

## Фаза 2: что изменено

### 1. Корректность baseline
L1 получил AUC 0.30–0.34. Главная причина — max по кадрам при обучении на всех кадрах чистых роликов:
длинные (чаще чистые) ролики получают больше попыток ложного пика.

| Проблема | Исправление | Флаг (по умолчанию) | Тест |
|---|---|---|---|
| Длинный чистый ролик весит в обучении пропорционально числу кадров | Каждая группа (уникальное видео, дубликаты свёрнуты) весит одинаково, её версии делят этот вес, классы поровну | `train.weighting: group` (`frame` — старый режим) | `test_length_control.py::test_group_weighting_*` |
| Скор видео = max по кадрам растёт с длиной | `topk_null`: максимум блоковых top-k (фиксированный k), нормированный по числу блоков через null-CDF чистых роликов: `s = G(stat)^n_blocks`. G — по OOF-кривым чистых роликов **только из train** (внутренний CV) | `infer.pooling: topk_null` (`max` и `topk` — для сравнения) | `test_pooling_watchdog_*` |
| Порог/null могли подбираться по оценочным данным | Порог и null калибруются внутренним grouped CV на train каждого фолда (в `train` — на обучающих данных) | — | `test_cv.py` |
| Длительность как скрытый признак | Сторож: ρ(скор, длительность) на чистых роликах и AUC одной длительности — в каждом отчёте | `cv.duration_watchdog_rho: 0.3` | `test_pooling_watchdog_*`, `test_risk_is_local_*` |
| Свежие float32 и кэшированные float16 признаки давали разный вход | Эмбеддинги приводятся к точности кэша сразу после извлечения | — | `test_e2e`: переименованная копия → тот же риск |
| Время кадра `idx/fps` при переменном fps | Время из PTS (`CAP_PROP_POS_MSEC`) в fallback-загрузчике | — | `test_simple_clip_uses_pts_*` |
| Схема L1 (`t_sec`, `t_all`) не распознавалась → у позитивов пропали бы таймкоды | Парсер знает схему `video_id,file,label,t_sec,md5,group,t_all,conflict,raw` | — | `test_l1_schema_labels_csv` |
| Порядок строк, кадров и групп | Фолды строятся по отсортированным id групп, кадры строго по времени | — | `test_cv_invariant_to_row_order` |
| GT или имя файла в инференсе | Имя файла не входит ни в признаки, ни в ключ кэша (только md5 содержимого) | — | переименованная копия даёт идентичный риск |
| Версия кэша | `FEATURE_VERSION` входит в ключ кэша: при изменении извлечения старый кэш не подхватится | — | — |

Скор не «переворачивается» ради AUC.

Синтетика (шумовые кривые чистых роликов разной длины, 5 сидов): ρ(скор, длина) составил 0.35–0.56
у `max`, 0.56–0.69 у `topk` с фиксированным k (сам по себе смещение **не убирает**) и −0.09…0.08
у `topk_null`. AUC с синтетическим событием у всех ≥ 0.98. **Это синтетика, не реальные данные.**

### 2. Признаки по зонам и признаки изменения (выключены по умолчанию)
- **`change`** — группа входа: по каждому виду 1−cos(e_t, e_{t−Δ}) (Δ = 2 и 8 с) и контраст
  «до/после» 1−cos(среднее [t−Δ, t), среднее [t, t+Δ)) (Δ = 1 и 3 с). Считается из кэша эмбеддингов,
  переизвлечение не нужно. Включение: `model.input_groups: [sims, emb, dyn, change]` (конфиг E1).
- **Зонные виды** `features.zone_views: [desk, safe, cashier_area, door]` — кропы по bbox зон A06.
  **Нет зоны → вид неизвестен (NaN), а не «пусто».** Флаги наличия (`avail`) добавляются автоматически.
  Извлечение: `extract --zones auto` (через `ml.detect` + `ml.track`). У аугментированных копий геометрия
  зон неверна, поэтому их зонные виды остаются неизвестными. Пиксельных координат, цвета одежды
  и яркости как признаков нет.

### 3. Разметка
- Позитивная секунда даёт локальную гауссиану ±3 с. Остальная часть ролика — маска; надзор уровня видео —
  MIL в temporal head. Чистые ролики — негативы.
- Дубликаты образуют одну группу. Разные таймкоды (Х-4/Х-47: 57 и 68 с) помечаются `time_conflict`,
  решает человек. Политика `labels.time_conflict_policy: both` (обе секунды остаются якорями, ничего
  не выбрано) или `video_only` (кадровый надзор снят).
- **Тип** учится только по подтверждённым меткам (`type_id`, `type_status` пуст или `confirmed`).
  Метки `type_status=vlm/pseudo` попадают в `pseudo_type_id` и используются только при
  `train.use_pseudo_types: true`; тогда события помечаются «предварительно». Без меток —
  `type_id="V99"`, `type_source="none"`. Zero-shot — только подсказка с `trained: false`.

### 4. Генератор кандидатов `propose(clip)`
3–8 моментов на видео (`Event`, `extra.role="candidate"`, `type_id="V99"`, окно ±2 с для VLM).
Режимы `propose.mode`:
- `risk` — пики обученной риск-кривой;
- `change` — кривая изменений без обучения (контраст эмбеддингов «до/после» + начало движения,
  ранжирование внутри видео);
- `hybrid` (по умолчанию) — до 4 пиков риска, затем изменения, минимум 2 с между кандидатами.

Без checkpoint работает только `change`, уверенность ≤ 0.3. Это не детекция и не вердикт: слабый скор
не отсекает видео от остального анализа. Метрика — recall кандидатов в ±1.5 с от GT при ≤ 3/5/8
на видео (в cv и bench).
Политика таймкода (`peak` | `onset` | `change_onset`) выбирается **замером** (`timecode_by_policy`),
по умолчанию `peak`.

### 5. Протокол
Не больше трёх заранее описанных конфигураций (`config.yaml: experiments`):

| ID | Описание |
|---|---|
| E0 | baseline: логрегрессия по кадрам на SigLIP2, равный вес групп, пулинг `topk_null` |
| E1 | E0 + признаки изменения `change` |
| E2 | temporal head (TCN + MIL) на признаках E1 |

Repeated stratified group k-fold (по умолчанию 5 фолдов × 3 повтора, дубликаты — одна группа).
Пороги и null подбираются внутренним CV на train каждого фолда. Валидация идёт только по оригиналам,
без аугментаций. Режимы пулинга считаются по одним и тем же OOF-кривым, без переобучения.

## Команда замера для L2 (одна очередь GPU)
```bash
python -m ml.temporal.extract --videos data/raw --labels data/labels.csv        # кэш признаков (один раз)
python -m ml.temporal.check_split                                                # группы, конфликты, утечки
python -m ml.temporal.bench --experiments E0,E1,E2 --folds 5 --repeats 3 --inner 3 \
       --latency-videos data/raw --n-latency 5                                   # -> reports/temporal_bench.json
```
- **Сравниваем:** E0, E1, E2, а внутри каждой — пулинги `max` (старый), `topk`, `topk_null`
  и политики таймкода `peak`/`onset`.
- **Выход:** таблица в stdout и `reports/temporal_bench.json`. Для каждой конфигурации — среднее ± std
  по повторам:
  - FP и FN при порогах внутренних фолдов;
  - AUC по пулингам;
  - hit@1/2/3 с по политикам таймкода;
  - recall кандидатов @3/5/8 по режимам `risk`/`change`/`hybrid`;
  - ρ(скор, длительность) на чистых роликах и AUC одной длительности;
  - мс модели на видео;
  - пик VRAM при обучении.

  `--latency-videos` дополнительно мерит полный `score()` + `propose()` (с извлечением SigLIP2) и пик VRAM.
- **Тип:** точность не меряется, пока нет подтверждённых меток (`type_note` в отчёте).
- **Как решать:** переключать дефолты (`propose.mode`, `infer.pooling`, `infer.timecode_policy`,
  `model.input_groups`) и обучать прод-чекпоинт (`python -m ml.temporal.train --kind baseline|temporal`)
  только при измеренной пользе. Обязательные условия: без роста FN и без предупреждения сторожа
  длительности. Пока checkpoint нет, `score()` отдаёт `([], [])`.
- **Стоимость** (замер на CPU контейнера, 4 потока, синтетика реального размера: 40 групп, 3 версии,
  D=768): E0 — 51 с, E1 — 55 с на один повтор 5×(3+1); при 3 повторах примерно 2.5–3 мин каждая.
  Цифра для E2 — в итоге PR. На RTX 4060 и реальных данных не мерилось.

## Публичные функции
```python
from ml.temporal import score, propose, warmup, status
risk, events = score(clip, zones=None, budget_s=None)   # контракт; без checkpoint -> ([], [])
cands = propose(clip, zones=None, budget_s=None)        # 3–8 Event-кандидатов для VLM/правил
warmup(); status()                                      # status(): ok | no_checkpoint | backend_mismatch | too_short | error
from ml.temporal.infer import propose_status            # диагностика propose()
```
- **Пустой ответ при неполном анализе — это «не проанализировано», а не «нарушений нет».**
  Полнота лежит в `status()["coverage"]` / `propose_status()["coverage"]`:
  `{analyzed_until_s, duration_s, fraction, complete}`. При `complete=False` (обрезка по бюджету)
  или статусе не `ok` fusion не должен превращать результат в `no_violation`.
- **Mock-режим** (`SENTINEL_MOCK=1`) включается только явно — в тестах и демо. Production сам на mock
  не переключается.

## Ограничения
- Данных мало, разметка — одна секунда, тип не размечен. Метрики шумные; смотрите на std по повторам.
- Zero-shot подсказки не калиброваны на виде сверху. Это признаки и подсказка, не классификация.
- CPU-режим: 1 fps и только вид `full`. Недостающие виды становятся «неизвестно», качество ниже.
- Кривая изменений реагирует и на выключение света. Для кандидатов это допустимо (момент стоит проверить),
  для вердикта — нет.

## Решения, принятые автономно
- Пулинг по умолчанию — `topk_null`. Это прямое исправление п.1; `topk` без нормировки длину не убирает
  (синтетика).
- null-статистика блочная (τ = 4 с, k = 4 окна по 0.5 с), скор видео — максимум тех же блоков. Так
  статистика согласована с null; глобальный top-k давал остаточную корреляцию с длиной.
- Без checkpoint `propose()` возвращает кандидатов только из кривой изменений. Это детерминированный
  выбор моментов для проверки, а не скор нарушения. `score()` без checkpoint по-прежнему пуст.
- Прод-порог калибрует `train` внутренним CV; отчёт CV для этого больше не нужен (`deploy_threshold`
  удалён).
- Зоны считаются по оригинальному ролику; у аугментированных копий зонные виды неизвестны.
