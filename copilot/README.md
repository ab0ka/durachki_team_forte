# A14 — `copilot/` — Sentinel Copilot (опциональный модуль)

> Подключение, форматы, переменные, отключение, команда замера для L2: [`INTEGRATION.md`](INTEGRATION.md).

Локальный ассистент проверяющего. Объясняет, **почему отмечено** и **какая норма** (или честно «без
пункта»), отвечает только из фактов задачи и подтверждённых источников (`norms/` A13), при нехватке
данных говорит «По имеющимся данным это установить нельзя». На вердикт, таймкод и тип не влияет, GPU у
анализа не отнимает. Есть «Заключение проверяющего» в markdown/HTML и подсказки вопросов для UI.

**Статус:** опциональный, по умолчанию в проде выключен (`enabled: mock`). Генерация — общая
Qwen3-VL-4B через `ml.vlm.service.chat` (A11), низкий приоритет. Нет модели или GPU занят → честный
негенеративный режим `retrieval`. Дообучения не было, реальная генерация на GPU не запускалась, цифр
качества нет (см. «Проверки»).

## Решения (фаза 2, приняты автономно)
1. **Модель — только общая VLM.** `auto` = `ml.vlm.service.chat` → (локальный llama-server, если задан).
   Отдельная llama.cpp-модель в процессе включается только явно: рядом с VLM на 8 ГБ она не помещается.
2. **Нет модели → retrieval, а не 501.** Так сказано в спецификации. Ответы собираются из фактов и
   найденных норм, режим виден в `status` и первой строкой ответа. `llm.no_model_mode: unavailable`
   возвращает 501. Copilot, выключенный флагом, по-прежнему отдаёт 501.
3. **Низкий приоритет.** Busy-probe от A02/A03 (идёт анализ) или занятый GPU → ответ без генерации
   с пометкой (`busy_policy: retrieval`). Ожидание длится не дольше `wait_s`, анализ не тормозится.
4. **Честные нормы.**
   - Цитата помечает связь: `catalog` (норма каталога для типа события, со списком событий) или
     `retrieved` (найдено поиском, связь не подтверждена).
   - Статусы `candidate` и не сверенные цитаты называются «требует сверки».
   - Типы с `legal_status: disabled` и без правил → «без пункта».
   - Источники `search_snippets` целиком «не сверено». Разделы «Не цитаты/пересказы», «Реквизиты»,
     «TODO» и преамбула не цитируются.
5. **Неполный анализ ≠ «нарушений нет»; unknown ≠ полный.** Учитываются `meta.completeness` (A01),
   `complete/partial` (A03), `coverage`, `analysis_complete`, failed. Guard режет «нарушений нет» при
   неполном анализе или найденном нарушении, а также «всё в порядке» без оговорки при неизвестной
   полноте.
6. **«Почему отмечено» — только из данных пайплайна:** факты, детекторы со скорами, состояние VLM
   (`meta.ui.evidence_overlays` A12 / `meta.violation_extra` A01) и спорные места. Если данных нет,
   ничего не достраивается.
7. **Инъекции — это данные.** Внешний текст санитизируется и помещается в блоки данных. Отказы о
   невидимом детерминированы и даются до модели. Всё, что модель выдаст, проходит guard. Предложение
   со ссылкой на несуществующее событие или норму вырезается целиком.
8. **Временный адаптер к `ml.vlm.runtime` выключен:** он опирается на внутренности A11 и работает
   только с уже загруженной («тёплой») VLM.
9. **HTML-заключение встраивает кадры** (локальный файл для проверяющего), только валидный JPEG.
   Выключается `report.html_include_frames: false`.
10. **LoRA вне критического пути:** запуск только если у L2 останется время, без замера не
    рекламировать. Формат промпта для датасета — `prompts.build_messages`.

## Проверки (реально выполнены)
- `python -m pytest copilot/tests -q` → **214 passed, 1 skipped** (Python 3.11, CPU, без весов и сети).
  Пропущенный тест — на реальном `norms/`, он запускается, если папка есть в ветке.
- `ruff check copilot` по правилам A01 → чисто.
- Синтетический `eval_grounding`: mock/retrieval 100%, guard ничего не режет. «Плохая модель» (скрипт):
  safety 100%, guard урезает 89% ответов.
- Не проверено: генерация Qwen3-VL через `ml.vlm.service.chat` (его ещё нет у A11), латентность и VRAM,
  e5 на реальных весах, отсутствие влияния на время анализа. Это замеряет L2 (INTEGRATION.md §5).

## Для интегратора — коротко
- **A11:** экспортировать `ml.vlm.service.chat(messages, max_new_tokens, timeout_s, priority, …)` и,
  по возможности, `available()`. Контракт — в INTEGRATION.md §1.
- **A02/A03:** `copilot.service.set_busy_probe(lambda: <идёт анализ>)`. Copilot подключать тем же
  ключом и сессией (уже так в ветке A02).
- **A15:** опционально `GET …/suggestions` вместо захардкоженных вопросов и `?format=html` для
  заключения. Пометку режима показывать как есть (она в `answer`).
- **A13:** `rules` с `verified: true` и `legal_status: confirmed` автоматически станут «подтверждённой
  нормой». Сейчас подтверждённых нет, поэтому copilot честно пишет «требует сверки» или «без пункта».
- Удалить `copilot/_contract_fallback.py` после мерджа контрактов A01.
